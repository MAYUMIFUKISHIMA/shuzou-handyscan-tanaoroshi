# 現場PC1台での運用準備

## 決定事項

現場ではPC1台を使う。PythonアプリとSQLiteはそのPC内に置き、ブラウザーは同じPCからアクセスする。GitHubで複数端末に共有するのは開発コード・設計・skillであり、現場DBは共有しない。担当者名は現在の試作では作業記録用の自己申告で、本人認証ではない。初期版の権限方式と運用代替の可否は[完成判定表](release-acceptance.md)のD04で確定する。PC1台という決定だけで権限要件を免除しない。

## 起動

Python 3.12以上をインストールする。Windowsではstart.cmdを起動、macOS/Linuxでは `./start.sh` を実行する。Windows起動ファイルはpyランチャーを使用する。ない場合はリポジトリルートで `python -m inventory.launcher` を実行する。

既存DBがある場合、起動前にdata/backupsへ検証付きバックアップを作成する。バックアップできなければ起動を止め、元DBを残す。初回はバックアップ対象がないのでそのまま起動する。

```sh
python -m inventory.launcher --backup-dir /別媒体のバックアップ先
```

同じPC内のバックアップだけではPC故障に備えられない。業務終了後にも `python -m inventory.backup data/prototype.sqlite3 別媒体の新しいファイル.sqlite3` を実行し、別媒体へ保管する。自動削除は実装していない。保存期間・頻度・損失許容・復旧時間は完成判定表D07で受入試験前に確定する。

## ブラウザー

現行ChromeまたはEdgeを推奨。Web Locks APIで同じブラウザープロファイル内の操作タブを1つに限定する。2枚目は入力を禁止し、操作タブを閉じると自動で引き継ぐ。未対応ブラウザーは操作を有効にしない。異なるブラウザーやプロファイルはこのロックを共有しないため、現場では使用するブラウザープロファイルを1つに固定する。サーバー側では別途revision競合を検知する。

商品番号・数量の下書きは棚卸IDと区画ごとにlocalStorageへ保存し、再読込時に復元する。担当者・端末名・直前の棚卸も復元する。記録成功時は該当下書きを削除する。保存失敗時はメッセージを表示する。ブラウザーのサイトデータを削除すると下書き・列設定・未確認送信内容も失われる。DBは別に保持される。

CSV列設定は全件検証後に「列設定を保存」を押す。次回、同じ文字コードで必要な列名がすべて存在する場合のみ復元する。自動で取り込まず、毎回プレビューで確認する。設定はそのブラウザー内に保存される。

商品番号・名称検索と、未棚卸/競合・差異ありの絞り込みが使える。未登録保留は専用欄から確認する。

## PC交換・復元

1. 旧PCで未確認送信を解決し、入力途中の下書きを記録する。サーバーを止める。
2. 検証済みDBバックアップと、使用していたGitコミットを記録する。
3. 新PCへ同じコミットとPythonを用意し、バックアップを新しいパスにコピーする。既存DBは上書きせず退避する。
4. `python -m inventory.launcher --db 復元したDB.sqlite3` で起動し、棚卸番号・件数・確定結果を照合する。
5. ブラウザー内の下書きや列設定は移行されない。設定をやり直す。旧PCと新PCで同時に実運用しない。

Windows実機と物理的に別のPCでの復元は未検証。自動テストでは別DBファイルへのバックアップ・再読込を確認している。

## ブラウザーテストの再現

アプリ自体にNode.jsは不要。開発テストのみNode.jsとPlaywrightを使う。

```sh
npm ci --ignore-scripts
npx playwright install chromium
npm run test:browser
```

OSにブラウザー依存ライブラリが不足する場合はPlaywright公式のインストール手順に従う。既存Chromiumを使う場合はCHROMIUM_PATHに実行ファイルを指定できる。テストは一時DBを使い、終了時に削除する。実データを使わない。

## 性能測定

`python -m scripts.benchmark` で架空5000商品・20000履歴の上限付近を確認する。2026-10-31、今回のLinux環境の測定では、取り込み約0.029秒、20バッチの記録と訂正合計約15.54秒、集計約0.013秒、区画完了と確定約0.112秒、DB約6.8MBだった。現場PCの速度保証ではない。長期蓄積や複数棚卸を大量保持した状態の性能は別途確認する。
