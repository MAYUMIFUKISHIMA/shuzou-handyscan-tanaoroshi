# 当日V1: PCバーコードで棚卸し、売りex検証先へ取り込む

## 範囲

ユーザーはPC接続バーコードリーダーを使用でき、売りexの取り込み形式確認と検証用取り込みが可能と回答した。当日の経路はPC入力に絞る。BT-W250用アプリ・正式システム全体の完成は引き続き別の未完了条件として管理する。

## 手順

1. start.cmdまたは `python -m inventory.launcher` で起動する。PCのブラウザーはChrome/Edgeを使う。
2. バーコードリーダーをキーボード入力モード・読取末尾Enterに設定する。メモ帳等で先頭ゼロと終端キーを確認する。
3. 売りexから棚卸対象を出力し、商品番号・名称・システム数量の列を割り当てて取り込む。作業者・区画・対象件数を確認する。
4. 商品番号欄へフォーカスし読取。Enterで数量欄へ移動し、実数を入力してEnterで保存する。読取だけでは数量を加算しない。再読取は訂正確認が入る。未登録は保留する。
5. 全区画を完了確認し、差異・保留・競合を確認して確定する。実数ゼロは明示入力する。
6. 「売りex用CSVの出力設定」を開き、確認した列順・列名・固定値・文字コード・ヘッダー・実数/増減数を設定し、確認根拠を記録する。列は上から順番に出力される。
7. 設定した形式でCSVを保存する。出力した内容・形式・版・ハッシュはDBに残り、形式変更は拒否する。同じ形式で再保存はできるが、再取り込みしてよいことを意味しない。
8. 売りexの検証先へ取り込み、対象全件の反映後数量を確認する。不一致・部分成功・結果不明はそのまま再投入せず、反映行を特定する。

## 現在の確認待ち

利用者回答で列順は商品コード・商品名・数量、ヘッダーあり、数量は棚卸実数と確認した。正確なヘッダー文字列、文字コード、倉庫・日付等の追加必須項目は未確認。画面の「元CSVの列名で設定」で、取り込み時に選んだ列名と文字コードを再利用する候補設定を作れる。これは売りexで受理されると確定した設定ではなく、検証先で確認する。出力エンジンは架空の仕様でテスト済みだが、売りex互換の確認ではない。複数倉庫など商品番号だけで一意にならない入力は現時点では対応しない。追加の変換・引用規則等が判明したら実装する。

検証先のURLや認証情報は共有されていないため、売りex側の操作は未実施。現場PCへGitの最新版を取得し、この手順に沿って検証する必要がある。

## 当日V1の完了条件

- 現場のリーダーで番号を正しく読み、数量保存・訂正・ゼロ・未棚卸の区別を確認する。
- 正式仕様に合わせたCSVで、検証先の対象全件が期待する実数となり、対象外の意図しない変更がない。
- 結果不明時に二重取り込みせず、出力版・取り込み結果・照合結果を記録する。

ここまでの証拠が揃うまで「売りexへ取り込みまで完成」としない。本番利用には完成判定表の権限・停止運用・復旧等の条件も必要。実作業では基準出力前から反映確認まで対象の移動・在庫更新を止める。
