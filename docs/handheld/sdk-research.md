確認日: 2026-11-01（日本時間）。端末型番BT-W250はユーザーの現場情報による。OS・SDKは前回回答で未入手/未確定。

## アップデート手順の確定事項（2026-11-02）

添付 `AS_58805_BT-WHD1_OM_KJ_JP_1113_1.pdf`（136231、1113-1、表題「BT-WHD1 のアップデート手順 V3.00版」、2ページ）を確認。

- p1: 「PC上にBT-WHD1製品版の各ソフトウェアがインストールされていない場合、アップデートは動作しません」と明記。新規PCにアップデータだけで導入可能とは案内しない。
- p2: PCシミュレータ更新完了後、デスクトップに実機用 `BT-W_SDK-HT.msi` とシミュレータ用 `BT-W_SDK-PCSim.msi` が作成され、それを実行する手順。MSIがZIPのファイル一覧にないことを、SDKが提供されない根拠にはできない。
- p2: 同版インストール済みで削除画面が出る場合はキャンセルする。削除すると製品版の再インストールが必要との記載。既存環境を確認せずアンインストールや更新を勧めない。
- データ転送ソフトのみ「アップデータではなくインストーラで提供」と記載。これをSDK本体の新規導入可否へ拡張しない。

実際にユーザーが取得したパッケージは4.53、手順書の表題は3.00。SDK生成の説明と製品版前提は確認できたが、4.53での正確な画面・挙動は未実行。まずWindows PCの「インストールされているアプリ/プログラムと機能」でBT-WHD1関連の導入状況を調べる。未導入なら正規製品版の入手/再発行をメーカーへ確認する。既存導入ありの場合は保存データを保全し、対応更新手順を確認してから進める。

今回受領した一覧333件には実機MSIの直接収録はなく、PCシミュレータsetup.exeなどはある。更新後にMSIが生成される説明で、この一覧との関係が明らかになった。SDK本体の取得・Windowsインストール・ビルド・実機検証は依然未実施。

## 開発ガイド追加受領（2026-11-02）

ユーザー添付 `Techniques_Tips_KJ_JP_AS_117082.pdf` を確認。BTシリーズの開発方式を説明するガイドであり、BT-WHD1アップデート手順そのものではない。PDFのみ受領し、アップデータZIPはこの会話には添付されていない。

- p4: 端末へ配置する組込アプリは無線LANがない環境でも利用可能と説明。
- p6–7: Windows OS向け組込開発はVS2008（Professional/Team System）、プログラム開発キットをアドインして使用、言語VB/VC#/VC++、ローカルDBとしてSQL Server Compact/SQLiteを掲載。
- p6: 組込アプリの通信構成としてファイル通信、キーエンス専用通信、FTP通信、共有フォルダーへのファイルコピーを掲載。これによりFTP/共有の利用が公式の構成候補であると確認できた。ただし、現場のRNDIS中継機器・既存FTP設定を専用アプリから使うAPI/権限/パス/共存条件までは確定しない。
- p12以降: BT-H1Aノーコード方式も紹介。承認済みV01〜V10を満たすことを実証した資料ではなく、専用アプリ方針やC#第一候補を自動変更しない。

BT-WHD1アップデータだけで新規導入できるかは、このガイドには記載が見つからず未確認。次はアップデータZIPを実行せず展開し、README/更新手順と `BT-W_SDK-HT.msi` 等の収録有無を確認する。ファイルが収録されていることと新規導入の正式対応は別に判断する。SDKインストール・ビルド・実機確認は未実施。添付PDF本体と抽出全文はGitへ登録しない。

### 最小アプリへ進む具体的な条件

C# + .NET Compact Framework 3.5を第一候補とし、公式C#読取サンプルを起点にする。BT-WHD1本体と公式サンプルを入手し、正規のVS2008 Professional SP1を用意したWindows開発PCで、メーカー指定の更新と実機SDKを導入する。SDK/IDEの利用条件を確認し、インストーラーの署名を検証する。まず公式サンプルを変更せずビルドし、実機読取とキー操作を確認してから専用アプリへ進む。

今回添付されたものはPDFでありSDKインストーラーではない。LinuxクラウドにはVS2008/MSBuildも実機SDKもなく、ここで端末用ビルドを実行できたとは扱わない。仮のAPI宣言や空のDLL参照で実機対応プロジェクトを完成扱いしない。読み取り制御・通信制御・ソフトウェアマニュアルによりAPI、FlashDiskの保存完了条件、アプリ配布/起動/共存手順をさらに確認する。

p79–80のUSB転送と現場のUSB Ethernet/RNDIS Gadget経由FTPは異なる。既存FTPサーバー/共有MST・RESを専用アプリから利用する方法は未確定。ガイドp66のFTP/IISの記述はパッシブリモコン用であり、棚卸アプリ全体のFTP方式の指定と解釈しない。

受領確認・再送排除・訂正履歴の契約は専用V1仕様を維持。既存Gakkenファイルや共通設定を変更せず、専用パスとアプリ識別子は公式配布手順確認後に設定する。SDK同梱のライセンスキーやDLLをGitへ登録しない。
