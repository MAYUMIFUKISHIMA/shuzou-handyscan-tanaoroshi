# 現場端末の写真から確認した事項

根拠: ユーザーが共有した本体表面・背面ラベル・起動後デスクトップの3枚、および追加共有されたログイン画面・ログイン後メニューの2枚。写真自体はリポジトリに保存せず、端末に関する観察のみ記録する。

| 項目 | 観察 | 判定 |
| --- | --- | --- |
| メーカー・型番 | 背面ラベルにKEYENCE CORPORATION、BT-W250 | 写真で確認済み |
| 本体のラベル | i3 Handy | 写真で確認済み。アプリ版やライセンスの証拠ではない |
| 起動直後の画面 | デスクトップに「マイ デバイス」「Gakken i3 Handy」「Universal Updater」のショートカット | 写真で確認済み |
| OS | Windows系組込みOSに見えるデスクトップ | 外観からの推定のみ。OS名・版・CPU・SDKは未確定 |
| アプリ起動 | ユーザID・パスワードのログイン画面と、ログイン後のGakken i3 Handyメニュー | 画面を確認。認証方式・アプリ版は未確認 |
| メニュー | QR検品、バッチ検品（CSV取込型）、実績・マスタ系機能、各種設定 | 項目の存在を写真で確認。詳細機能・ファイル仕様は未確認 |

## 次に確認する順序

1. 確認済みメニューの「バッチ検品（CSV取込型）」と「実績・マスタ系機能」の詳細画面を確認する。
2. 商品一覧/マスター受信、棚卸/数量入力、結果送信/出力の機能があるかを確認する。名称だけで対応機能を推定しない。
3. 中継機器とPC側ソフト、取り込み/出力ファイル仕様、既存アプリの利用条件を確認する。
4. 既存アプリで対象マスター受信・計数・結果回収が可能なら、PC側アダプターを作る方式を優先評価する。対応しなければSDKを用いた専用アプリ方式を評価する。

既存アプリがあることだけでV1のハンディ部分が実装済みとは扱わない。数量訂正、ゼロと未棚卸、保存、再送、版識別に対する受入条件を満たすことが必要。Universal Updaterの機能や設定は未確認で、更新・再インストールの操作は今回行っていない。

## 既存アプリ利用の適合判断

「バッチ検品（CSV取込型）」という名称は取り込み機能の存在を示す手掛かりであり、任意の棚卸CSVに対応する証拠ではない。検品が予定数量との照合やスキャン回数集計のみで、実数の任意入力・訂正を備えない可能性もある。CSVの列・商品コード対応・名称表示・数量の意味、実績回収形式と未棚卸の区別を確認してから、PC側の変換アダプターを実装する。設定の変更や実績削除は、現在の業務と保存データを確認するまで行わない。

## 追加確認: バッチ検品と実績送受信メニュー

ユーザー共有の追加写真から、以下の項目の表示を確認した。転送実行や設定変更は行っていない。

- バッチ検品メニュー: 伝票毎出荷検品、ページ毎出荷検品、全頁検品済確認機能。出荷検品向けの項目で、棚卸実数を任意入力する機能があるとはまだ判断しない。
- 実績送受信・マスタ系メニュー: 検品データ投入(FTP)、検品データ投入(USB)、実績転送(FTP)、実績転送(USB)。FTP/USBの選択肢があることは確認したが、現場の有効な接続方式・中継機器との対応は未確認。

V1再利用の残確認は、(1)投入ファイルの列・文字コード・配置先・単位、(2)実数の任意入力/訂正/ゼロ・未棚卸、(3)実績ファイルの列と数量の意味・結果保持、(4)投入/回収の失敗と再送の挙動。PC側転送ソフトと中継機器は後日共有予定。メニューの存在だけで成功確認済みにしない。

次は伝票毎出荷検品の最初の画面を確認して、商品照合と数量入力の流れを調べる。実績転送やデータ投入は既存の現場データへの影響が分かるまで試行しない。

## 追加確認: 出荷検品（伝票毎）の開始画面

共有写真の表示は「検品開始（開始コード入力待）」「検品スタートキーをスキャンしてください」、検品済伝票数0。画面右下にver.4.0.0、操作案内にF1:機能、Fn:Flash、F4:入力切替、F2:リセット、ENT:手入力、F3:終了が見える。これは当該画面のバージョン表示であり、OS/SDK版の確認ではない。

この経路では商品コードの読取に入る前に開始コードが必要と読み取れる。ENT:手入力の存在は開始コードの手入力を示す可能性があり、任意数量の入力・訂正が可能という根拠にはならない。開始コードの値や生成規則、投入CSVとの対応は未確認。任意の値や資材コードを開始コードとして流用しない。既存の検品スタートキーまたはPC側の投入データ仕様を確認した後、数量入力画面へ進めるか調べる。

## 追加確認: 現場PCと周辺機器

共有写真から確認した内容（画面操作・転送は実行していない）:

- 小型のUSB接続らしき機器の側面に「FLIRC」と読める表示がある。型番・USB認識名・役割は未確認で、ハンディデータ転送用の中継機器とは断定しない。
- Windowsエクスプローラーの01_出荷ハンディ用配下に、01_ピッキングリスト、02_HT用ファイル作成、G1_学研ツール、Z0_説明資料、ZZ_ツール設定等がある。
- 「出荷ハンディ用ファイル作成v2」というExcelファイルがあり、種類表示はExcelマクロ有効形式を示すように見える。正確な拡張子とVBA内容は未確認。シートはピッキング、HTファイル作成、ツール設定が見える。
- 表示中のピッキングシートには売りex対象ファイル、処理データファイル（売上データ.xlsx）、処理データ作成のボタンがある。これは現在の出荷用途の画面であり、棚卸用形式とは判断しない。
- 赤字は「対象ファイルの形式が誤っています」のメッセージが出た場合の再取得案内。写真から、そのエラーが実際に発生中とは判断しない。

次の確認はHTファイル作成シートの画面とG1_学研ツールのフォルダー内容を優先する。可能なら既存ブックのコピーと説明資料を読み取り解析し、投入CSVの列、開始コード生成規則、出力先、転送ツールを特定する。原本のマクロ実行や接続設定の変更を調査の前提にしない。実データ・共有フォルダーの機密情報はGitへ保存しない。

## 添付ブック解析による更新

Excel本体とマニュアルの静的解析を実施。現場マニュアルはFTP投入・FTP実績伝送を指定し、USB選択による停止への注意がある。元ブックは読み込みDT.xlsxを別の学研v7ブックへ渡す前処理であり、ハンディ投入データの生成はv7に依存する。詳細と根拠は[ブック解析結果](workbook-analysis.md)。過去のメニュー観察よりこの資料の運用記述を優先し、USBを利用できるとは扱わない。

## 学研ツール本体から判明した事項

開始キーと投入形式・i3Edge系の共有経路を[静的解析](gakken-v7-v6-analysis.md)で特定した。写真の機器の正体や接続成功を証明するものではない。実績の実数列と任意数量の入力は未確認で、既存アプリの棚卸適合を確定しない。
