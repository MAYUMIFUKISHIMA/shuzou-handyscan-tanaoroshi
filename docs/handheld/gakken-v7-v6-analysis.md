## 1. 開始キーと列の対応

v7 App_Custom.OptionalProcess_After_AllFileLoadは入力シートのA列（伝票番号）をAT列へコピーする。設定!D3はAT、App_Main.GetDataはその列をStartKeyへ読み、MakeKenpinSheetでKENPINの1・2列目へ入れる。INDEX作成関数も同じ値を開始・終了キーへ入れる。したがって、この設定の開始キーは出荷伝票番号である。添付に保存された入力行でもAとATの一致を集計確認した（具体値は転載しない）。

主な入力加工:

| 元列 | 中間列 | 内容 | 後続 |
| --- | --- | --- | --- |
| A | AT | 伝票番号 | 開始キー・外部伝票番号 |
| AB | AU | 商品CD | SKU |
| AC | AV | 商品名 | DESCR（出力時半角変換あり） |
| AE | AW | 数量 | QTY/検品数 |
| AD | AX | 入数 | インナー結束 |
| 商品マスタ参照 | AZ等 | JAN/ITF等 | ALTSKU/ケース結束 |

未登録商品は商品マスタまたはセット商品マスタの検索結果で検品対象外フラグとなり得る。セット商品の展開もある。資材の既存コードを入れるだけでは対象に残る保証がなく、資材用バーコード対応と除外条件の検証が必要。

## 2. 最終投入ファイル

Cmn_ListKenpin.WriteKenpinSheetとWriteINDEXSheetは、Cmn_Tools.WriteFileToTSVを呼ぶ。ADODB.StreamのCharsetはShift-JIS指定。ヘッダー行を含み、最終行には改行を追加しない。Windowsでの実際のバイト表現を含む互換性は現物出力で照合する。

| ファイル | 出力列数 | 内容 |
| --- | --- | --- |
| KENPIN.TXT | 18 | 下記の検品明細 |
| INDEX.TXT | 4 | 検品開始キー、検品終了キー、納品書総頁数、モード |

KENPINの列順（38列定義のうち実際に書く先頭18列）:

1. 検品開始キー
2. 外部伝票番号
3. 案件識別子
4. IDR（個体識別）フラグ
5. 重量後決めフラグ
6. サイズ後決めフラグ
7. 輸送種
8. 熨斗印字枚数
9. 熨斗テンプレートID
10. 送り状フラグ
11. 商品コード
12. ALTSKU1
13. ALTSKU2
14. ALTSKU3
15. DESCR
16. ケース結束
17. インナー結束
18. 検品数

INDEXは同じ開始キーの連続行をまとめ、開始キー＝終了キー、総頁数1、モード2を設定する。「モード2」の端末上の意味は、このExcelだけでは確定しない。検品数はPCから配布する数量であり、現場で数えた棚卸実数ではない。

## 3. 現在のPC側設定と通信

v7設定!C22は×で、コード上はUSBメモリではなくi3Edgeの存在確認・共有先MSTへのコピー経路を選ぶ。v6設定!C12はedgeLinksで、設定先のshare/i3HT/RESを読む。具体的接続先は原本にのみ保持する。

```mermaid
flowchart LR
 A[出荷用中間Excel] --> B[学研v7]
 B --> C[KENPIN.TXT / INDEX.TXT]
 C --> D[i3Edge系共有 / i3HT / MST]
 D -->|ハンディ側マニュアルはFTP投入| E[BT-W250]
 E -->|マニュアルはFTP実績伝送| F[i3Edge系共有 / i3HT / RES]
 F --> G[学研v6で実績集約]
```

これはファイル設定・コードとマニュアルから整理した構成であり、接続成功を試験したものではない。写真のFLIRC表示機器がこの共有を提供する機器かは未確認。ハンディ側のUSBメニューは既存マニュアルに停止注意があり、USBへ切り替えない。

v7の共有へのコピーは既存のINDEX.TXT、KENPIN.TXT、OKURI.TXTを削除し得る。生成処理を調査目的で不用意に実行しない。原本の出荷設定を棚卸用に書き換えない。

## 4. 実績回収の処理

v6 App_Main.MainはRES直下をパターン別に読み、以下のシートへ集約する。サブフォルダーは再帰検索しない。ReadFolderDataはShift-JIS設定で読み、先頭行をヘッダーとして結合する。商品数量の意味を固定した棚卸変換ではない。

| 主なファイルパターン（設定識別子等を省略） | 出力シート |
| --- | --- |
| ht_kenpin_jisseki_*.txt | 伝票毎実績集約 |
| ht_kenpin_sku_jisseki_*.txt | SKU毎実績集約 |
| ht_kenpin_box_jisseki_*.txt | 個口毎実績集約 |
| ht_id_recognize_history_*.txt | 個体識別番号実績集約 |

読み込んだファイルをRES/bk/日時へ移動する処理がある。保存ダイアログでキャンセルした場合には移動したファイルを戻す処理があるが、任意の中断・例外で必ず復旧するという検証はしていない。静的解析のために集約ボタンを押す必要はない。実績の調査は元ファイルのコピーで行う。

## 5. 棚卸V1への適合判定

判明したもの: 開始キー、投入ファイル名・列順・区切り・文字コード指定、PC側の共有配置/回収経路、実績ファイルの候補。

未判明: 任意実数の入力と訂正、予定数を超える/下回る場合の記録、ゼロと未棚卸、検品中断時の出力、実績数量列の意味、リセットと再検品後の履歴。端末アプリ本体のコードは添付に含まれず、v6には実績データそのものもない。

そのため、学研アプリを棚卸に利用可能とはまだ断定しない。配布する検品数を基準在庫に設定し、その値を棚卸実数として取り込む実装は行わない。検品完了するまで予定数に合わせて読む運用も代替にしない。
