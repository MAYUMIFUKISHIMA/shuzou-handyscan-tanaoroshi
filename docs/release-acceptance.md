# 初期リリースの完成判定表

作成日: 2026-10-31（日本時間）
対象: 現場PC1台、BT-W250、売りex CSV連携を用いる出荷資材棚卸。
現在の判定: **未完成（PC試作段階）**。

基本設計の第3・15節と本書を完成判定の正本とする。文書更新の承認と現場の実施条件・受入合格の承認は別である。本書の未決項目を、文書を作ったことだけで承認済みにしない。

## 1. 担当と判定方法

- 開発担当: 実装、再現可能なテスト、結果と既知不具合の提出。
- 現場業務責任者: 対象範囲、入出庫停止、担当・確認手順、運用上限の決定。
- 売りex担当: 正式CSV仕様、反映後照合、部分成功・取消・再取り込みの確認。
- PC運用担当: 対応環境、バックアップ、復元、起動手順の確認。
- 現場受入責任者: 全必須条件と証拠を確認し、対象コミット・設定版を指定して最終承認。

担当者の氏名は未指定。同一人物の兼務は可能だが、役割と承認記録を残す。D04の決定に応じて必要な役割分離を行う。開発担当によるテスト成功のみで現場受入を代行しない。

判定順序は、D01〜D07の確定 → 必須機能の実装・事前検証 → 対象環境でA01〜A08の受入 → 最終承認とする。独立した実装・試験は未決事項の確定前でも進められるが、未確定の受入条件を合格にしない。

## 4. 証拠の記録様式

各条件ごとに以下を記録する。機密データそのものはGitへ入れず、安全な保管先とハッシュを記す。

| 項目 | 記入内容 |

## 5. 完成・リリース判定

- D01〜D07の未決ゼロ、A01〜A08すべて合格、現場受入責任者の承認を必要とする。
- 数量誤更新・欠落・二重計上・未棚卸のゼロ扱い・復旧不能につながる未解決不具合はリリース不可。
- 軽微な残件は影響・回避方法・担当・対応予定・承認者を記録する。必須条件の不合格を免除する用途には使わない。
- 機能の除外は明示した範囲変更として基本設計と本表を改訂する。未実装だから対象外と扱わない。
- 受入済みのコード・設定を変更した場合、影響する条件を再試験し、リリース対象版を更新する。
- 完成を承認した版をタグ等で識別し、実行手順・バックアップ・既知の制約・証拠を引き継ぐ。承認前に完成済みタグを付けない。

最終承認記録（現在は空欄）: 対象コミット/設定版、D決定記録、A判定・証拠一覧、軽微残件一覧、受入責任者氏名、承認日、運用開始日。
