# CSV・実機の確認票

確認結果は[完成判定表](release-acceptance.md)のD01〜D03とA02/A03/A05へ記録する。本票のチェックだけでシステム全体を完成扱いにしない。

## 売りexのCSVサンプル受領時

- エクスポートとインポートを別々に保管し、版・画面名・対象範囲を記録する。
- 列順、必須列、文字コード/BOM、改行、引用符、空欄、数値書式を確認する。
- 商品番号の先頭ゼロ、倉庫、ロット、単位、小数桁、負の基準在庫を確認する。
- 数量が絶対実数か増減か、同じCSVの再取り込み時の挙動を確認する。
- 部分失敗、未指定商品の扱い、ゼロ、差異ゼロ、取消方法を確認する。
- 実データをリポジトリへ登録せず、形式を保った架空データを作る。
- 検証環境で取り込み前後の数量を比較し、往復テストを完成させる。

## BT-W250確認

公式候補ページ: https://www.keyence.co.jp/products/mobile-computers/handheld-computers/bt-w/models/bt-w250/

2026-10-31、このURLの取得はプロキシから403で拒否された。内容は確認できておらず、URLの有効性や仕様の根拠にはしていない。

現物の型番、OS/ファームウェア、既存アプリ、接続PCのOS、USB/通信台/無線LAN、導入済み開発ツールとSDKライセンスを確認する。メーカーの対応資料を取得した後に、適合する開発方式を決める。

実機試験: 読取文字列、終端文字、キー入力、日本語表示、数量訂正、保存直後の再起動、通信中断、同じ結果の再送、転送確認前のデータ保持、古い棚卸データの拒否。既存アプリや現場データを消さず、検証用データで行う。

## 転送契約の試案

PC側のreceive操作は記録配列を一括受信する。各記録はid（UUID）、device、code、location、quantity（十進文字列）、operator、supersedes（訂正元ID配列）を持つ。操作全体に棚卸IDとrevisionを指定する。すべて検証した後に一括保存し、一件でも不正なら全件を取り消す。

現在のHTTP操作はローカル試作用。実機の転送方式と切り離した論理契約であり、BT-W250への配布形式は未確定。棚卸の配布版、端末記録日時、チェックサム付き受領通知、未登録コード保留の仕様を実機方式決定時に追加する。

実機なしの模擬実装と調査状況は[端末準備](handheld/preparation.md)、実機試験は[試験票](handheld/device-test-plan.md)を参照。

現場マニュアルではFTP投入/回収を指定し、USB選択による停止注意がある。[添付解析](handheld/workbook-analysis.md)を参照し、メニューにUSBがあることだけで切り替えない。
