# csv-integration

## 使用する場面

CSV取り込み・出力・項目対応・文字コードの変更時。

## 前提

リポジトリルートのAGENTS.md、docs/status.md、docs/design.mdを読む。業務仕様の正本はdocs/design.mdとし、食い違いがあれば根拠を確認して整合させる。既存チェックアウトを利用し、実データや秘密情報はコミットしない。

## 手順

1. docs/design.mdの第6・8・10・11節を読み、サンプルの有無と売りexの更新単位を確認する。
2. 列名、列順、文字コード、BOM、引用符、改行、必須項目、数量単位、実数/増減を仕様表として記録する。未確認値を推測で確定しない。
3. サンプル未提供の間は架空CSVと仮の形式定義で進め、売りex互換を確認済みとしない。
4. 標準CSVパーサーを使い、文字列の単純分割を避ける。商品番号の先頭ゼロを保持し、数量は十進数として検証する。
5. 不正文字、必須値欠落、重複キー、数量不正を行別に報告する。全件検証後に一括反映し、部分反映しない。
6. 確定結果のみを出力する。未棚卸をゼロに変換しない。形式定義と出力版を保存し、増減CSVの二重取り込みを防ぐ運用を明記する。
7. inventory-testingで文字コード、引用符を含む名称、先頭ゼロ、不正行、往復変換を検証する。

## 完了条件

形式定義と未確認項目が記録され、変更対象の検証が実行されている。売りex実機への取り込み未確認なら、その制約を残す。

成果・検証結果・未確認事項・次の作業をdocs/status.mdに記録する。別端末で再現できる手順を残す。
