# handy-terminal-development

## 使用する場面

端末の技術選定、画面、バーコード取得、保存、配布、転送の作業時。

## 前提

リポジトリルートのAGENTS.md、docs/status.md、docs/design.mdを読む。業務仕様の正本はdocs/design.mdとし、食い違いがあれば根拠を確認して整合させる。既存チェックアウトを利用し、実データや秘密情報はコミットしない。

## 手順

1. docs/design.mdの第3・5・7・11節を読み、型番、OS、ファームウェア、既存アプリ、通信方法を確認する。
2. メーカー公式の資料でSDK、開発ツール、ライセンス、配布方法、保存領域、対応通信を調べる。資料URL、版、確認日、実機との対応を記録する。
3. Web/PWAやAndroidの対応を推測しない。既存アプリやデータを保護し、小規模な検証用アプリで方式を実証する。
4. バーコード取得、物理キー入力、商品名と単位表示、保存成功表示を実証する。保存失敗時は入力を保持する。
5. 端末再起動後の記録保持と未送信記録の回収を検証する。端末ID、記録ID、棚卸ID、データ版を転送に含める。
6. 受領確認前に記録を削除しない。通信中断・再送・古い対象データ・競合を検証する。
7. SDKや実機が利用できない場合は独立した業務処理と転送仕様を進め、実機試験を未実施として残す。

## 完了条件

採用方式の根拠と再現手順があり、実機で行った試験と未実施を区別している。SDKや現場アプリの無断再配布はしない。

成果・検証結果・未確認事項・次の作業をdocs/status.mdに記録する。別端末で再現できる手順を残す。
